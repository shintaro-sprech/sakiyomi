## 2026-11-03 案を2つ反映すると、材料の遅れが二重に入る

1. **何を作ろうとしたか**：Claude が出した組み替え案を、担当者がボタン1つで計画に反映できるようにする
2. **Claude にどう指示したか**：Claude Code に「壁打ちした内容を全部対応して」と頼み、案のカードには「変更の組み合わせ」を持たせる形で作ってもらった
3. **何が起きたか**：Claude Code が自分でブラウザを操作して確かめたところ、どの案にも「材料が2日遅れる」という出来事そのものが含まれていた。2つの案を続けて反映すると、遅れが4日になる
4. **期待とどう違ったか**：案は「出来事への対策」であってほしかったが、出来事と対策が1つの変更リストに混ざっていた
5. **どう対処したか**：Claude に渡すツール `present_options` を、出来事（`event`）と対策（各案の `changes`）に分ける形に変えた。反映するときは、まだ計画に入っていない出来事だけを足す。1つの提案の中で1つの案を反映したら、ほかの案は閉じる。カードには「何もしないと」の影響も出すようにした

## 2026-11-03 方針の見直し：計画・スケジュール・評価の3段にする

1. **何を作ろうとしたか**：本物の Claude で「材料が2日遅れる」の相談が通り、案が3つ出るところまでできた
2. **Claude にどう指示したか**：動きを見た計画担当の目線で、「これだと対象の型番の予定をずらしているだけに見える。今月必ず出すもの（在庫切れ）と来月切れるものから計画を立て、その通りに進めれば納期を守れるか、当月の採算はどうなるかまで出したい」と伝え、Claude Code と相談役のモデルの両方とすり合わせた
3. **何が起きたか**：スケジューラは試算のたびに全注番を全設備で組み直しており、整合は取れていた。足りないのは入力と評価だった。在庫と消費から出す需要の段、優先の区分、形状から形状への段取り時間、出勤人数、お金がなかった
4. **期待とどう違ったか**：「出来事に対して予定がどう動くか」は出せても、「この計画で今月を乗り切れるか、いくら残るか」には答えられなかった
5. **どう対処したか**：残りの日数に合わせて順番を決めた。先に、需要と優先の区分（A 今月必達／B 来月在庫切れ／C 余力）、形状の段取り表、粗利（当月完成分の売上 − 材料費 − 労務費（残業25%・休日35%増し）− 設備の時間費）を入れる。次に、工程のまとまりごとの日別の出勤人数を入れる。最適化の計算、設備ごとのサイクルタイム、Lot の分割は見送る

# 構成（2026-11-03 決定）

| 決めたこと | 内容 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript。画面は React + Vite | 画面とスケジューラを同じ言語で書き、同じ計算を使い回す |
| 置き場所 | Cloudflare Workers 1つで画面と API を配る（公式テンプレート `create-cloudflare --framework=react`） | 公開するときは URL が1つで済む |
| データ | 架空のサンプルを、使う人のブラウザ（localStorage）に保存する | ログインも共有の DB もいらない。個人情報を持たない |
| スケジューラ | `src/engine/` に純粋な関数として書き、Vitest でテストする | 同じ入力なら必ず同じ計画になる |
| ガント | React で描く | 設備×時間の表示と、バーを押したときの動きを自由に作れる |
| Claude | Messages API のツール呼び出し（`claude-opus-5-5`、adaptive thinking、effort は medium）。ツールはブラウザで実行し、Worker は中継だけをする | Claude が「計画を見る → 変更を試算する → 案を出す」を道具で進める。数字は画面と同じスケジューラから出る |
| 鍵と回数 | API キーは Worker の secret にだけ置く。中継ではモデル・指示文・道具・出力の長さを固定し、IP ごとに1分20回まで（Workers Rate Limiting）。拒否されたときは `fallbacks: "default"` で代わりのモデルに回す | 公開した窓口が、誰でも使える中継にならないようにする |
| Excel | SheetJS（Apache-2.0）を公式の配布元から入れ、必要になったときだけ読み込む | 最初の表示を軽くする |
| パッケージ | npm | ローカルで動かすとき、追加の道具がいらない |
| 画面の部品 | Mantine（MIT）と Tabler Icons（MIT）。工程のマス・工程全体の列・ガント・キャラクターだけを自前で描く | ボタン・入力欄・表・パネルを自己流で作らない。ライト／ダークの切り替えも Mantine の仕組みを使う |
| 表示 | ライトが基本。ダークはヘッダーのボタンで選んだときだけ | 事務所で Excel と並べて使い、デモ動画にも映す |
| アクセシビリティ | WCAG 2.2 AA を目安にする（文字の対比 4.5:1、12px 以上、キーボード操作、閉じたパネルは inert、動きを減らす設定を尊重） | 誰が使っても読めて操作できるようにする |
| キャラクター | 相談パネルのアシスタントは、このアプリのために描いた SVG。待機・考え中・話し中の3つの状態を CSS で動かす | 他社のマークやマスコットは使わない |

## フォルダ

```
src/engine/     スケジューラ、進み具合、仮の変更。React を使わない
src/assistant/  Claude に渡すツールの定義、ツールの実行、会話の往復
src/state/      ブラウザへの保存と、判断の記録
src/ui/         画面（React + Mantine）
src/data/       Excel の読み込みと書き出し
worker/         Claude との中継と回数制限
sample-data/    架空のサンプルデータ
docs/           この記録、開発メモ、ハッカソンの決まり
```

## データ

Excel の11のシートと同じ形で持つ。最後の3つ（実績・受注・販売在庫）は表示にだけ使い、計画は読まない。

- 品目：型番・形状・売価・材料費・在庫・月間の出荷数・材料在庫（どの注残にも引き当てていない分を、作れる個数で。空でもよい。材料の入荷日のない注残は、材料が手元にある）・材料の調達日数（発注してから届くまでの暦の日数。空でもよい）
- 工程表：型番ごとの工程の並びと、1個あたりの加工時間
- 設備：設備ID・名前・担当する工程（複合機は複数。どれも同じ班に入る）・速さ（工程表の1個あたりの分に対する速さ。1が工程表のとおり）・段取りの既定の分・1時間の運転費（動かした時間に掛かる電気や刃物などの費用。設備の償却は含めない）・直前の型番（その設備で最後に加工した型番。空でもよい）
- 段取り：工程ごとに、前の形状から次の形状へ替えるときの分（表にない組み合わせは設備の既定の分、同じ型番は0分）
- 班：班名・担当する工程・いつもの人数（どの班にも入っていない工程は、人数で絞らない）
- 出勤：班名・日付・その日の人数（いつもと違う日だけ書く）
- 注残：注番・型番・数量・納期・材料の入荷日（未投入の分）
- Lot：Lot番号・注番・数量・今いる工程・その工程に着いた日
- 実績：Lot番号・工程番号・設備ID・開始・終了・良品数・不良数（Lot が通り終えた工程だけ）
- 受注：受注番号・注番・取引先・販路（直販か代理店）・数量・希望納期・回答納期（空なら未回答）。完成見込みと回答納期を比べて、約束に間に合うかを出す（`src/engine/records.ts`）
- 販売在庫：取引先（代理店）・型番・基準日・在庫・月間の実売・注文の目安の日数（空なら30）。代理店へ出荷しても売れたとは限らないので、本当の需要は代理店の実売で見る。基準日から今日まで実売で減らした在庫に、その代理店の受注（注文済みでまだ出荷していない分）を足し、実売の何日分かと、目安の日数まで減って注文が来る見込みの日と数（1か月分の実売）を出す（`src/engine/records.ts`）。計画の在庫は、これまでどおり品目の月間の出荷数で減らす

工程ごとの完了数・仕掛・未着手・完成は、Lot から計算する（`src/engine/progress.ts`）。未着手は、注残の数量のうち、まだ Lot にしていない数。進捗タブの一番上の表は、仕掛を「工程（班ごとにまとめる）× 急ぐ理由」で数える。急ぐ理由は、区分 A を、在庫切れの日が納期より前なら「在庫切れ」、そうでなければ「納期」に分け、B と C はそのまま使う。

## 計画・スケジュール・評価

1. **需要と区分**（`src/engine/demand.ts`）：型番ごとに、在庫と月間の出荷数から在庫切れの日を出す。注残を納期順に並べ、「在庫＋それより前の注残」が切れる日と納期の早い方を、その注残の必要日とする。必要日が今月なら A、来月なら B、それ以降なら C。あわせて、来月末までの出荷に、在庫と全部の注残の残りを足しても足りない数と、在庫と注残が尽きる日を出す（`replenishments`）。計画の完成の時刻には左右されない数の差し引きで、計画に入れると製造注残の追加になる
2. **スケジュール**（`src/engine/scheduler.ts`）：Giffler-Thompson 型の割り当て。毎回、いちばん早く終われる作業を探し、その設備でそれより前に始められる作業どうしを、①最優先にした注番 ②区分（A → B → C）③「必要日までの余裕（日）× 重み」と「段取り（時間）×（1 − 重み）」の和 ④必要日・注番・Lot番号、の順で比べて1つ選ぶ。比べるのは、その設備でいちばん早く始められる時刻から、いちばん早く終われる時刻までの 3/4 までに始められる作業に限る（長い作業の前で、急ぎの作業を待って設備を丸1日空けないため）。設備は担当工程のどれの作業も受け持ち、かかる時間は工程表の分を設備の速さで割ったもの。工程間の待ち時間は、次の工程が別の設備に移るときだけかける。段取りは、その作業の工程の段取り表から引き、各設備の最初の段取りは直前の型番から決める。未投入の分は、その注番の Lot番号に続く番号（Lot がなければ `L注番-1`）を予定の Lot番号として組む。設備は1台に1人が付いて動くので、稼働日には、班の設備が同時に動く台数をその日の人数までに抑える（作業が終わった人は、同じ班の別の設備に移れる。休日出勤は、その設備に1人が出る）。ある作業で班の最後の1人が埋まるときは、同じ班のほかの設備の作業も③までの順で比べ、人を優先の高い作業に回す。稼働時間の外と休日は止まり、残業・休日出勤・設備の停止・後回し・班の人数は変更として当てる。数学的な最適化ではなく、決まった手順で全注番を同時に組む
3. **評価**（`src/engine/economics.ts`）：今日が属する暦の月について、粗利 ＝ 今月完成する分の売上 − その材料費 − 労務費 − 設備の運転費。労務費は、動いている設備1台に1人として、通常の時間・残業（割増25%）・休日出勤（割増35%）に分けて計算する（割増率は設定で変えられる）。設備の運転費は、動いた時間 × 1時間の運転費。固定費は配賦しない。あわせて、納期に遅れる注番と、来月末までの在庫の欠品（日ごとに出荷で減り、完成した Lot で増える）を出す。来月末までの出荷に、在庫と全部の注残を足しても足りない型番は、足りない数を注残に足した計画を組み直して着手日を出し、材料在庫で足りなければ、着手日から材料の調達日数を引いた稼働日を材料の発注期限とする（`src/engine/plan.ts` の `releaseTiming`）。

## 仮の変更（Change）

材料の遅れ、数量の変更、設備の停止、残業、休日出勤、最優先、後回し（指定日まで着手しない）、製造注残の追加、班の人数（応援や休み）の9種類。Claude のツール、案のカード、判断の記録は、すべてこの形で変更を扱う。案のカードでは、聞いた出来事（event）と対策（changes）を分けて持ち、反映するときは、まだ計画に入っていない出来事だけを足す。カードの効果（遅れ・今月の粗利・残業と休日出勤の時間の増減）は、画面と同じエンジンで計算する。

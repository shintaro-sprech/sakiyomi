```

src/state/      ブラウザへの保存と、判断の記録

docs/           この記録、開発メモ、ハッカソンの決まり
```

## データ

Excel の14のシートと同じ形で持つ。実績・受注・販売在庫・商談・商談の履歴・月ごとの受注は表示にだけ使い、計画は読まない。

- 品目：型番・形状・売価・材料費・在庫・月間の出荷数・材料在庫（どの注残にも引き当てていない分を、作れる個数で。空でもよい。材料の入荷日のない注残は、材料が手元にある）・材料の調達日数（発注してから届くまでの暦の日数。空でもよい）
- 工程表：型番ごとの工程の並びと、1個あたりの加工時間
- 設備：設備ID・名前・担当する工程（複合機は複数。どれも同じ班に入る）・速さ（工程表の1個あたりの分に対する速さ。1が工程表のとおり）・段取りの既定の分・1時間の運転費（動かした時間に掛かる電気や刃物などの費用。設備の償却は含めない）・直前の型番（その設備で最後に加工した型番。空でもよい）
- 段取り：工程ごとに、前の形状から次の形状へ替えるときの分（表にない組み合わせは設備の既定の分、同じ型番は0分）
- 班：班名・担当する工程・1つの直に出る人数・休日に休日出勤で1つの直に出る人数（どの班にも入っていない工程は、人数で絞らない。直ごとの人数の違いは持たず、出勤の行はその日のどの直にも効く）
- 出勤：班名・日付・その日の人数（いつもと違う日だけ書く）
- 注残：注番・型番・数量・納期・材料の入荷日（未投入の分）
- Lot：Lot番号・注番・数量・今いる工程・その工程に着いた日
- 実績：Lot番号・工程番号・設備ID・開始・終了・良品数・不良数（Lot が通り終えた工程だけ）
- 受注：受注番号・注番・取引先・販路（直販か代理店）・数量・希望納期・回答納期（空なら未回答）。完成見込みと回答納期を比べて、約束に間に合うかを出す（`src/engine/records.ts`）
- 販売在庫：取引先（代理店）・型番・基準日・在庫・月間の実売・注文の目安の日数（空なら30）。代理店へ出荷しても売れたとは限らないので、本当の需要は代理店の実売で見る。基準日から今日まで実売で減らした在庫に、その代理店の受注（注文済みでまだ出荷していない分）を足し、実売の何日分かと、目安の日数まで減って注文が来る見込みの日と数（1か月分の実売）を出す（`src/engine/records.ts`）。計画の在庫は、これまでどおり品目の月間の出荷数で減らす
- 商談：商談ID・商談名・取引先・担当者・型番・ステージ（引き合い・見積・試作・量産の内示・受注・失注。最初の4つが進行中）・受注予定日・量産数量（月）・取引先の種別（既存・新規）・引き合いの経路・用途・メモ・登録日・ステージを変えた日・延期回数。受注予定日を後ろへ動かすと延期回数が1増え、前へ戻しても減らない。型番が空・量産数量が0以下・使えないステージは不備として数えず、品目にない型番・受注予定日を過ぎた進行中の商談・90日動かないステージは注意として数える（`src/engine/deals.ts`）
- 商談の履歴：商談ID・項目・変える前・変えた後・日時。登録の行と、変わった項目ごとの行を足すだけで、書き換えない。どの日の商談の姿にも戻せる（`dealAsOf`）。ステージを変えた日と延期回数は、空なら履歴から出す
- 月ごとの受注：年月・型番・拠点・受注数量・出荷数量。拠点は、複数の工場を持つ会社が工場ごとに分けるためのもので、空なら「自社」

工程ごとの完了数・仕掛・未着手・完成は、Lot から計算する（`src/engine/progress.ts`）。未着手は、注残の数量のうち、まだ Lot にしていない数。進捗タブの一番上の表は、仕掛を「工程（班ごとにまとめる）× 急ぐ理由」で数える。急ぐ理由は、区分 A を、在庫切れの日が納期より前なら「在庫切れ」、そうでなければ「納期」に分け、B と C はそのまま使う。

## 計画・スケジュール・評価

1. **需要と区分**（`src/engine/demand.ts`）：型番ごとに、在庫と月間の出荷数から在庫切れの日を出す。注残を納期順に並べ、「在庫＋それより前の注残」が切れる日と納期の早い方を、その注残の必要日とする。必要日が今月なら A、来月なら B、それ以降なら C。あわせて、来月末までの出荷に、在庫と全部の注残の残りを足しても足りない数と、在庫と注残が尽きる日を出す（`replenishments`）。計画の完成の時刻には左右されない数の差し引きで、計画に入れると製造注残の追加になる
2. **スケジュール**（`src/engine/scheduler.ts`）：Giffler-Thompson 型の割り当て。毎回、いちばん早く終われる作業を探し、その設備でそれより前に始められる作業どうしを、①最優先にした注番 ②区分（A → B → C）③「必要日までの余裕（日）× 重み」と「段取り（時間）×（1 − 重み）」の和 ④必要日・注番・Lot番号、の順で比べて1つ選ぶ。比べるのは、その設備でいちばん早く始められる時刻から、いちばん早く終われる時刻までの稼働時間の 3/4 までに始められる作業に限る（長い作業の前で、急ぎの作業を待って設備を丸1日空けないため。暦の時間で測ると、間に土日があるときに 3/4 の点が土日に落ち、週明けすぐに始められる急ぎの作業が比べる相手から外れる）。設備は担当工程のどれの作業も受け持ち、かかる時間は工程表の分を設備の速さで割ったもの。工程間の待ち時間は、次の工程が別の設備に移るときだけかける。段取りは、その作業の工程の段取り表から引き、各設備の最初の段取りは直前の型番から決める。未投入の分は、その注番の Lot番号に続く番号（Lot がなければ `L注番-1`）を予定の Lot番号として組む。設備は1台に1人が付いて動くので、稼働日と、班が休日出勤で出る休みの日には、班の設備が同時に動く台数をその日の人数までに抑える（作業が終わった人は、同じ班の別の設備に移れる。休日出勤の手で呼んだ設備には、班の人数とは別に、直ごとに1人が出る）。ある作業で班の最後の1人が埋まるときは、同じ班のほかの設備の作業も③までの順で比べ、人を優先の高い作業に回す。稼働時間の外と休日は止まり、残業・休日出勤・設備の停止・後回し・班の人数は変更として当てる。数学的な最適化ではなく、決まった手順で全注番を同時に組む
3. **評価**（`src/engine/economics.ts`）：今日が属する暦の月について、粗利 ＝ 今月完成する分の売上 − その材料費 − 設備の運転費 − 残業代 − 休日出勤の人件費（直接原価計算。計画で増減する費用だけを引く）。いつもの直に出る人の給料は、夜勤の深夜割増も含めて計画では変わらない固定費なので引かず、休みや応援でも変わらない。残業代は、日勤の終業を過ぎて実際に動いた時間 × 賃率 ×（1＋残業の割増25%）。休日出勤は2つある。班の休日の人数は、休日の勤務の時間（日勤なら8〜16時、3交代を選べば一日中）を、設備が動いても動かなくても × 賃率 ×（1＋休日の割増35%）で払う。休日出勤の手で呼んだ設備は、その設備が少しでも動いた直に1人を呼び、その直の時間（日勤は始業から終業まで、3交代は8時間ずつ）をまるごと同じ率で払う。日勤で休日出勤の日に残業を足したときは、直をまるごと払ったうえで、終業を過ぎて実際に動いた時間も休日の割増で払う（終業を過ぎてからしか動かない日も、直は呼ぶ）。残業と休日出勤のうち22時〜5時には、深夜の割増25%を足す（労働基準法37条の率。割増率は設定で変えられる）。設備の運転費は、動いた時間 × 1時間の運転費。ほかの固定費も配賦しない。あわせて、納期に遅れる注番と、来月末までの在庫の欠品（日ごとに出荷で減り、完成した Lot で増える）を出す。来月末までの出荷に、在庫と全部の注残を足しても足りない型番は、足りない数を注残に足した計画を組み直して着手日を出し、材料在庫で足りなければ、着手日から材料の調達日数を引いた稼働日を材料の発注期限とする（`src/engine/plan.ts` の `releaseTiming`）。「今日の先読み」は、これらから今日手を打つことを並べる（`src/engine/focus.ts`）。期限が7日以内の材料の発注（2つまで）、納期に遅れる注番、7日以内に注文が来そうな代理店、注番の納期には間に合うが回答納期に遅れる受注、7日以内に始まる欠品の順で、4つまで。

## 商談からの需要

1. **受注確率**（`src/engine/winModel.ts`）：受注か失注になった商談ごとに、通った進行中のステージそれぞれの真ん中の時点で1行を作り、その時点の姿に戻した値と、最後の結果を組にする。特徴は、ステージにいる日数・登録からの日数・その時点の延期回数・受注予定日までの日数、ステージ・取引先の種別・引き合いの経路・用途（値ごとに1列）、メモの語（2件以上のメモに出て、8割を超えるメモには出ない語を、珍しさで重み付けし長さ1にそろえる）。商談を、受注の割合がそろうように最大5つの組に分け、ほかの組で学習した木で各組を当てて成績（AUC・平均適合率・50%で切ったときの適合率と再現率・対数損失・Brier スコアと、全部に同じ割合を付けたときの Brier スコア）を出す。進行中の商談には、その組ごとの木の確率の平均を付ける。結果で行の重みを変えないので、確率をそのまま数量に掛けられる。受注確率は「最終的に受注になる見込み」で、受注予定日までに決まる見込みではない
2. **期待数量と月ごとの見込み**（`src/engine/dealDemand.ts`）：進行中で不備がなく、受注予定日が今日から6か月後までで、確率が線引き（70%・80%・90%、初期は80%）以上の商談を数える。期待数量＝量産数量（月）×受注確率。型番ごと・担当者ごとに合計する。月に並べるときは、受注予定日の翌月から期間の最後の月まで毎月置き、受注予定日の月には量産数量の3か月分を初回の目安として置く（確率は掛けない）。受注予定日を過ぎた進行中の商談は、今日に決まる見込みとして数える。受注にしてから30日の商談は、注文が注残に入るまでの間として、受注した日に決まった確率100%の商談として数える。見込みは注残に足さず、計画と並べて見せるだけにする
3. **需要予測**（`src/engine/forecast.ts`）：月ごとの受注を、型番×拠点の系列にする（受注のない月は0）。最後の3か月を、それより前の月だけで1か月先ずつ当て（予測する月数によらず、比べるのは1か月先の当たり）、直近3か月の平均と、全系列をまとめて学習した勾配ブースティング木を比べる。木の誤差が平均より10%以上小さく、系列に24か月以上の実績があれば木を、そうでなければ直近3か月の平均を使う。3か月に満たない系列は、ある月の平均を参考値にする。木は、前の月・2か月前・3か月前・6か月前・12か月前の受注、直近3・6・12か月の平均、直近3か月のばらつき、前の月の出荷、暦の月、系列の何か月目かを見て、1か月ずつ先へ当てる（当てた値を次の月の前の月にする）。商談の見込みとは別の数字で、足し合わせない
4. **計画への受け渡し**（`src/engine/handoff.ts`）：商談からの見込み（線引き80%・6か月・受注予定月の翌月から）は、アプリを開いた日に版を作り、その日に商談が変わればその日の版を作り直す。需要予測は、計画担当が「計画に渡す」を押したときだけ版を作る。版は400日残し、種類ごとの最新の版は消さない。画面では、今月から7か月の型番×月に、注残（確定）・商談の見込み（量産と初回の目安に、それぞれ確率を掛けたもの）・需要予測を別の行に並べ、足した値は出さない。同じ分に2つ作った版は、後のものを今の版にする
5. **答え合わせ**（`src/engine/review.ts`）：選んだ日（初期は4週間前）の時点に商談を履歴で戻し、その日までに決着した商談で学習し直して、その日の確率を出す。確率70%以上で、その日の受注予定日が6か月後までの商談が、その後どうなったか（受注・失注・まだ）と、その日の受注予定日までに決まったかを、確率の帯・その日の受注予定日の月（過ぎていたものはその日の月）・型番ごとに数える。日ごとの写しを持たずに、履歴からその日の姿を作る
6. **商談の分析**（`src/engine/dealAnalytics.ts`）：今月までの12か月に決着した商談を、その前の12か月と比べる（受注・受注率・受注した量産数量・受注の売上の年額＝量産数量×売価×12）。月ごとの受注と失注、取引先・担当者・引き合いの経路・用途ごと、進行中の商談のステージごとの数
7. **在庫の見通しの「商談が決まると」**：計画に渡すのと同じ確率80%以上の商談で、型番ごとに、数えた商談の期待数量（月）と、在庫と注残の残りが尽きる日を、商談なしと商談込みで並べる。商談込みは、月間の出荷数の日割りに、数えた商談ごとに、初回の目安×確率を受注予定日から1か月の日割りで、量産数量×確率を量産が始まる月から日割りで足して減らす（`stockoutWithDeals`）。どちらも商談の期間の終わりまでを見て、商談込みで早まるときだけ出す

## 仮の変更（Change）

材料の遅れ、数量の変更、設備の停止、残業、休日出勤、最優先、後回し（指定日まで着手しない）、製造注残の追加、班の人数（稼働日の応援や休み）の9種類。Claude のツール、案のカード、判断の記録は、すべてこの形で変更を扱う。案のカードでは、聞いた出来事（event）と対策（changes）を分けて持ち、反映するときは、まだ計画に入っていない出来事だけを足す。カードの効果（遅れ・今月の粗利・残業と休日出勤の時間の増減）は、画面と同じエンジンで計算する。

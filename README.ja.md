# サキヨミ

**Excel で生産計画を立てている中小工場のための、生産計画アシスタントです。今月必要なものから計画を組み、この計画で納期を守れるか、在庫が切れないか、今月の粗利がいくらになるかを出します。「注番1045の材料が2日遅れる」と話しかけると、どの出荷がずれるかと、取り戻すための組み替え案が、粗利の増減と一緒に見えます。**

English: [README.md](README.md)

ハッカソン「Built with Claude: Japan 2026」（2026-11-02〜11-10）の期間中に作りました。

## なぜ作るのか

小さな工場では、計画は表計算に、判断のコツはベテラン1人の頭の中にあります。材料が遅れた、注文が増えた、設備が止まった、というときに、どの出荷がずれ、何を組み替えればよいかを言えるのはその人だけです。サキヨミは、誰でも聞けて、すべての注番への影響が見えて、なぜそう決めたかが記録に残る道具を目指しています。

## できること

- **今月の計画**：一番上に「今日の先読み」として、今日手を打つことを計画から出します。期限の迫った材料の発注、納期に遅れる注番、注文が来そうな代理店、回答納期に間に合わない受注、7日以内に始まる欠品です。注残を、在庫と月間の出荷数から「A 今月必要／B 来月必要／C それ以降」に分け、A から順に組みます。「これからの流れ」では、注番ごとに今日から完成見込みまでの棒を納期と並べ、型番の在庫が欠品する期間と材料の着く日も同じ時間の軸に載せます。そのうえで、今月の粗利（今月完成する分の売上から、計画で増減する費用＝材料費・設備の運転費・残業と休日出勤の人件費を引いたもの。いつもの直の給料は計画で変わらないので引きません）、納期に遅れる注番、来月末までの欠品、残業の時間（交代勤務では今月の完成数）と休日出勤の時間を出します。作る順番、班ごとに何人が設備に付くか、型番ごとの在庫の見通しも並べます。在庫と全部の注残を足しても来月末までの出荷に足りない型番には、足りない数といつまでに要るかを出し、材料在庫でまかなえるか、計画に足したときの着手日、材料の調達日数から逆算した材料の発注期限も添えます。ボタンひとつで製造注残として計画に反映できます。代理店へ出荷しても、売れたとは限りません。その下の表に、代理店ごとに、報告の在庫から実売で減った今の在庫、注文済みでまだ届いていない数、それが実売の何日分か、次の注文が来そうな時期を並べます
- **進捗**：一番上に、いま仕掛がどこにあるかの表を出します。横は班ごとにまとめた工程で、未投入から完成まで並べます。縦は、今月必要な注番のうち在庫切れが先のもの・納期が先のもの、来月、それ以降です。セルには個数とLot数を、工程名の下には今月分がその工程をどれだけ通ったかを出します。その下に、注残ごと、または型番ごとに、工程1・2・3…のマスを並べます。マスには、その工程の進み具合、そこにある仕掛の個数とLot数、何日も止まっているLotへの警告を出します。表のセルや工程名、工程全体の列やマスを押すと、仕掛Lotの一覧と、それぞれが次にいつ加工される予定かが開きます。注番の行には必要日を出し、在庫切れで決まるときは印を付けます。納期を押すと、その注番が満たす取引先の受注と回答納期を、完成見込みと比べて出します。型番の行には、欠品の見込みと、今月の出荷に、どの工程の仕掛まで要るか（未投入まで要るか、何個足りないか）を出し、足りない分を材料在庫でまかなえるかも添えます。Lot を押すと、その Lot が通った工程の実績が開きます。注番・型番・Lot での検索、完了を隠す、止まっている Lot があるものだけ、の絞り込みと、納期・完成見込み・工程全体での並べ替えができます
- **現場**：現場の今を3Dで見ます。左に材料、班ごとの区画に設備、右に完成品を置きます。各設備には、加工中の Lot と、その前で待っている Lot をガントと同じ色で載せ、状態（加工中・段取り中・空き・休み・停止）を信号灯で出します。加工中の設備は、ベンダーのラム、溶接ロボのアーム、ボール盤の主軸のように、その設備らしく動きます（動きを減らす設定では止めます）。床の下の一覧は、同じ中身を左から右へ同じ順に言葉で並べます。一覧か床で設備を選ぶと、両方で印が付きます。設備のモデルは、このリポジトリの Blender のスクリプト（[scripts/models/build_models.py](scripts/models/build_models.py)）で作ります
- **ガント**：設備×時間で計画を見ます。決まった手順で計画を組むスケジューラが、仕掛のLotと未投入の分を設備に割り当てます。稼働時間（日勤、または稼働日に一日中動く3交代）、休日、形状から形状への段取り替えの時間、工程間の待ち時間（次の工程も同じ設備なら待たない）、材料の入荷日、班ごとの出勤人数（設備1台に1人）を考えます。複合機のように1台で複数の工程を受け持つ設備も扱えます。設備ごとの速さに合わせて、工程表の時間を変えます。各設備は直前に加工した型番から始めるので、最初の段取りも数えます。バーには Lot・型番・形状・数量を出し、未投入の分は、投入の予定の Lot番号で出します。納期が近い注番は黄、遅れる注番は赤で出ます。設備名を押すと、その設備の予定を時間順に、形状から形状への段取りとあわせて出します。バーを押すと、その Lot が工程から工程へどう流れるかを出します。初日には今の時刻の線を引きます。バーにマウスを乗せるか、キーボードで移ると、詳しい内容が出ます。設備の予定には、段取りの回数と稼働時間の集計を出します。済んだ工程は、実績の設備と時刻で出します。流れの表から、進捗タブのその Lot の行へ移れます
- **Claude に相談**：出来事を日本語で話しかけると、Claude が今の計画を読み、出来事を試算し、どこが詰まっているかを調べて、休日出勤・優先の入れ替え・ほかの班からの応援、日勤の工場なら残業などの手を試します。そのうえで2〜3個の案を画面に出します。案のカードに出る効果（遅れ、今月の粗利、残業と休日出勤の時間の増減）は、Claude の文章ではなく、スケジューラが計算し直した数字です
- **判断の記録**：案を反映するときに、選んだ理由を一言残せます。変更の中身、Claude が示した理由、その代わりに起きること、担当者のメモを一緒に残すので、次の人が判断の筋道をたどれます。反映した変更は取り消せます
- **設定とデータ**：勤務の形（日勤とその時間か3交代、休日に出る班の勤務）と稼働する曜日、納期と段取りのどちらを重く見るか、工程間の待ち時間、賃率と残業・休日出勤・深夜の割増、品目の売価・材料費・在庫・出荷数、設備ごとの速さ・段取り時間・1時間の運転費・直前の型番、設備を止める設定、班の1直あたりの人数（平日と休日）と日ごとの出勤。データは、品目（材料在庫と調達日数を含む）・工程表・設備・段取り・班・出勤・注残・Lot・実績（Lot が通った工程）・受注（注番の後ろにある取引先の注文。販路は直販か代理店か）・販売在庫（代理店から届いた在庫と実売）の11シートの Excel に書き出し、読み込めます。班・出勤・実績・受注・販売在庫のシートはなくてもかまいません（[自分のデータで試す](#自分のデータで試す)）

## Claude の使い方

アプリの中心は、Messages API で Claude Opus 5.5（`claude-opus-5-5`、adaptive thinking）とやり取りするツール呼び出しです。

| ツール | 役割 |
| --- | --- |
| `get_situation` | 今の計画（今月の見通しと、足りない分の着手日・材料の発注期限、品目、段取り表、班と人数、設備の負荷、注番ごとの区分・必要日・完成見込み、代理店ごとの在庫と注文の見込み） |
| `get_order_plan` | 1つの注番の Lot が、いつどの設備で加工される予定か（人が空かずに待った作業も分かる）。仮の変更を当てた計画でも見られる |
| `simulate_changes` | 仮の変更を当てて、各注番の完成見込み（日時）と、今月の粗利・残業・休日出勤・深夜の時間がどう動くか |
| `present_options` | 案のカードを出す。聞いた出来事と、対策を分けて持つ |

ツールはブラウザの中で、画面を描いているのと同じスケジューラを使って動きます。そのため、Claude が話す数字と画面の数字は必ず一致します。Cloudflare Worker は中継だけを受け持ち、モデル・指示文・ツールの定義・出力の長さを固定し、送られてくる会話の形を確かめ、訪問者ごとに回数を制限します。拒否されたときの代替モデルも有効にしています。API キーがブラウザに渡ることはありません。

## 手元で試す

Node.js 22 以上が必要です。

```bash
npm install
cp .dev.vars.example .dev.vars   # .dev.vars に Anthropic の API キーを書く
npm run dev
```

http://localhost:5173 を開きます。進捗・ガント・設定・Excel はキーがなくても動きます。キーが要るのは「Claude に相談」だけです。最初は架空のサンプルデータで始まるので、相談パネルの一番上の「注番1045の材料が2日遅れると連絡がありました」を押してみてください。

スケジューラ・ツール・Excel の読み書きのテストは `npm test` で実行します。

## 自分のデータで試す

DB もログインもありません。工場のデータは、1冊の Excel のブックで出し入れします。

1. 「設定とデータ」で「Excel に書き出す」を押します。サンプルが `sakiyomi-data.xlsx` で出てくるので、これをひな形にします。
2. 各シートの2行目から下を、自分の工場の値に書き換えます。1行目の見出しはそのままにします。
3. 「Excel を読み込む」を押します。どこかに誤りがあると、何も置き換えず、「注残の5行目：納期を日付で入れてください」のように、シートと行を並べて出します。

| シート | 列 |
| --- | --- |
| 品目 | 型番・形状・売価・材料費・在庫・月間の出荷数・材料在庫（材料を数えていなければ空欄）・材料の調達日数（発注してから届くまでの暦の日数。空欄でもよい） |
| 工程表 | 型番・順番・工程名・1個あたりの分 |
| 設備 | 設備ID・設備名・担当工程（複合機は「切削、タップ」のように並べ、どれも同じ班に入れる）・速さ（0.1〜10。工程表のとおりが1、2割速いなら1.2。空欄は1）・段取りの分・1時間の運転費・直前の型番 |
| 段取り | 工程名・前の形状・次の形状・段取りの分 |
| 注残 | 注番・型番・数量・納期・材料入荷日 |
| Lot | Lot番号・注番・数量・今の工程番号（済んだら「完了」）・その工程に着いた日 |
| 班 | 班名・担当工程（「切断、曲げ」のように並べる）・人数（1つの直に出る人数）・休日の人数（休日出勤で1つの直に出る人数。出ないなら空欄） |
| 出勤 | 班名・日付・人数（その日の1つの直に出る人数） |
| 実績 | Lot番号・工程番号・設備ID・開始・終了・良品数・不良数 |
| 受注 | 受注番号・注番・取引先・販路（直販か代理店。空欄は直販）・数量・希望納期・回答納期 |
| 販売在庫 | 取引先（代理店）・型番・基準日（報告の日）・在庫・月間の実売・注文の目安の日数（在庫が何日分を切ったら注文するか。空欄は30） |

品目から Lot までの6シートは必ず要ります。班と出勤がなければ、人数の制約なしで組みます。実績・受注・販売在庫がなくても計画は同じで、Lot の実績、回答納期、代理店の見通しが出ないだけです。日付は 2026-11-12 か 2026/11/12、実績の開始と終了は 2026-11-12 09:30 の形で書きます。Excel の日付のセルでもかまいません。CSV は、Excel で開いて .xlsx で保存してから読み込みます。勤務の形（日勤か3交代）、稼働する曜日、賃率などの設定はブックに入らないので、同じ画面で入れます。読み込むと、判断の記録は消えます。

データの行き先：

- データ・設定・判断の記録は、このブラウザの localStorage にだけ保存されます。サーバーには置きません。
- 「Claude に相談」を使ったときだけ、会話と、Claude が求めたツールの結果が、Worker を通って Anthropic の API に送られます。ツールの結果には、注番・型番・数量・納期・Lot・設備・売価と材料費・賃率・取引先の名前など、計画の中身が入ります。Worker はそれを保存しません。Anthropic での扱いは、Anthropic の API の規約によります。

## データ

[sample-data/sample.ts](sample-data/sample.ts) のサンプルデータは、このリポジトリのために作った架空のものです。型番・設備・数量は実在の工場のものではなく、個人情報も含みません。日付は、アプリを開いた日からの相対で作ります。サンプルの工場は、平日に3交代で動き、土日は各班1人が日勤で休日出勤します。

## フォルダ

```
src/engine/     スケジューラ、進み具合、仮の変更（React を使わない TypeScript）
src/assistant/  Claude に渡すツールの定義、ツールの実行、会話の往復
src/ui/         画面（React）
src/data/       Excel の読み込みと書き出し
worker/         Claude API への中継（Cloudflare Worker）
sample-data/    架空のサンプルデータ
docs/           構成の記録
```

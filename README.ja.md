# サキヨミ

**Excel で生産計画を立てている中小工場のための、生産計画アシスタントです。今月必要なものから計画を組み、この計画で納期を守れるか、在庫が切れないか、今月の粗利がいくらになるかを出します。「注番1045の材料が2日遅れる」と話しかけると、どの出荷がずれるかと、取り戻すための組み替え案が、粗利の増減と一緒に見えます。**

English: [README.md](README.md)

ハッカソン「Built with Claude: Japan 2026」（2026-11-02〜11-10）の期間中に作りました。

## なぜ作るのか

小さな工場では、計画は表計算に、判断のコツはベテラン1人の頭の中にあります。材料が遅れた、注文が増えた、設備が止まった、というときに、どの出荷がずれ、何を組み替えればよいかを言えるのはその人だけです。サキヨミは、誰でも聞けて、すべての注番への影響が見えて、なぜそう決めたかが記録に残る道具を目指しています。

## できること

- **今月の計画**：注残を、在庫と月間の出荷数から「A 今月必要／B 来月必要／C それ以降」に分け、A から順に組みます。そのうえで、今月の粗利（今月完成する分の売上 − 材料費 − 労務費 − 設備の運転費）、納期に遅れる注番、来月末までの欠品、残業と休日出勤の時間を出します。作る順番、班ごとに何人が設備に付くか、型番ごとの在庫の見通しも並べます
- **進捗**：一番上に、いま仕掛がどこにあるかの表を出します。横は班ごとにまとめた工程で、未投入から完成まで並べます。縦は、今月必要な注番のうち在庫切れが先のもの・納期が先のもの、来月、それ以降です。セルには個数とLot数を、工程名の下には今月分がその工程をどれだけ通ったかを出します。その下に、注残ごと、または型番ごとに、工程1・2・3…のマスを並べます。マスには、その工程の進み具合、そこにある仕掛の個数とLot数、何日も止まっているLotへの警告を出します。表のセルや工程名、工程全体の列やマスを押すと、仕掛Lotの一覧と、それぞれが次にいつ加工される予定かが開きます
- **ガント**：設備×時間で計画を見ます。決まった手順で計画を組むスケジューラが、仕掛のLotと未投入の分を設備に割り当てます。稼働時間、休日、形状から形状への段取り替えの時間、工程間の待ち時間、材料の入荷日、班ごとの出勤人数（設備1台に1人）を考えます。納期が近い注番は黄、遅れる注番は赤で出ます
- **Claude に相談**：出来事を日本語で話しかけると、Claude が今の計画を読み、出来事を試算し、どこが詰まっているかを調べて、残業・休日出勤・優先の入れ替え・ほかの班からの応援などの手を試します。そのうえで2〜3個の案を画面に出します。案のカードに出る効果（遅れ、今月の粗利、残業と休日出勤の時間の増減）は、Claude の文章ではなく、スケジューラが計算し直した数字です
- **判断の記録**：案を反映するときに、選んだ理由を一言残せます。変更の中身、Claude が示した理由、その代わりに起きること、担当者のメモを一緒に残すので、次の人が判断の筋道をたどれます。反映した変更は取り消せます
- **設定とデータ**：稼働時間と曜日、納期と段取りのどちらを重く見るか、工程間の待ち時間、労務費と残業・休日出勤の割増、品目の売価・材料費・在庫・出荷数、設備ごとの段取り時間と1時間の運転費、設備を止める設定、班のいつもの人数と日ごとの出勤。データは、品目・工程表・設備・段取り・班・出勤・注残・Lot の8シートの Excel に書き出し、読み込めます

## Claude の使い方

アプリの中心は、Messages API で Claude Opus 5.5（`claude-opus-5-5`、adaptive thinking）とやり取りするツール呼び出しです。

| ツール | 役割 |
| --- | --- |
| `get_situation` | 今の計画（今月の見通し、品目、段取り表、班と人数、設備の負荷、注番ごとの区分・必要日・完成見込み） |
| `get_order_plan` | 1つの注番の Lot が、いつどの設備で加工される予定か（人が空かずに待った作業も分かる）。仮の変更を当てた計画でも見られる |
| `simulate_changes` | 仮の変更を当てて、各注番の完成見込み（日時）と、今月の粗利・残業・休日出勤がどう動くか |
| `present_options` | 案のカードを出す。聞いた出来事と、対策を分けて持つ |

ツールはブラウザの中で、画面を描いているのと同じスケジューラを使って動きます。そのため、Claude が話す数字と画面の数字は必ず一致します。Cloudflare Worker は中継だけを受け持ち、モデル・指示文・ツールの定義・出力の長さを固定し、送られてくる会話の形を確かめ、訪問者ごとに回数を制限します。拒否されたときの代替モデルも有効にしています。API キーがブラウザに渡ることはありません。

## 手元で試す

Node.js 22 以上が必要です。

```bash
npm install
cp .dev.vars.example .dev.vars   # .dev.vars に Anthropic の API キーを書く
npm run dev
```

http://localhost:5173 を開きます。進捗・ガント・設定・Excel はキーがなくても動きます。キーが要るのは「Claude に相談」だけです。最初は架空のサンプルデータで始まるので、相談パネルの一番上の「注番1045の材料が2日遅れると連絡がありました」を押してみてください。

スケジューラ・ツール・Excel の読み書きのテストは `npm test` で実行します。

## データ

[sample-data/sample.ts](sample-data/sample.ts) のサンプルデータは、このリポジトリのために作った架空のものです。型番・設備・数量は実在の工場のものではなく、個人情報も含みません。日付は、アプリを開いた日からの相対で作ります。読み込んだデータは、使う人のブラウザの中にだけ保存されます。

## フォルダ

```
src/engine/     スケジューラ、進み具合、仮の変更（React を使わない TypeScript）
src/assistant/  Claude に渡すツールの定義、ツールの実行、会話の往復
src/ui/         画面（React）
src/data/       Excel の読み込みと書き出し
worker/         Claude API への中継（Cloudflare Worker）
sample-data/    架空のサンプルデータ
docs/           構成の記録
```
